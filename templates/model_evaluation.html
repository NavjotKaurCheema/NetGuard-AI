Model Evaluation

Complete evaluation of 13 machine learning and deep learning models tested on CIC-IDS-2017 using 30 research-selected features. Includes model descriptions, comparative results, selection criteria, and deep-dive into the winning architecture.

Models Tested
Training Data: 2,017,889 flows (80% stratified split)  |  Test Data: 504,473 flows (20% held-out, never seen during training)  |  Features: 30 research-selected features (RF Gini + Mutual Information)  |  Preprocessing: Deduplication → Inf removal → Median imputation → log1p skewness correction → StandardScaler

ML Decision Tree

Single tree that recursively splits the feature space using Gini impurity. Fast and interpretable. Prone to overfitting without depth limits. Used as a strong baseline — Decision Trees historically achieve high accuracy on CIC-IDS-2017 (Ramesh IJIRT 2024: 99.99%).

ML Logistic Regression

Linear model estimating probability using the logistic function. Assumes linear separability — inappropriate for complex network traffic patterns. Included as a weak baseline to demonstrate the need for non-linear models.

ML Random Forest

Ensemble of 200 decision trees trained on bootstrap samples with random feature subsets. Majority vote determines final class. Robust to overfitting, handles imbalance via class_weight='balanced'. Standard IDS benchmark model.

ML Extra Trees

Like Random Forest but splits are chosen completely at random (no best-split search). Faster training than RF, sometimes better generalisation due to increased randomness reducing variance.

ML Gradient Boosting

Sequential ensemble — each tree corrects the errors of the previous. Highest precision of all models (0.9966) but extremely slow (5,603s). Impractical for large-scale deployment despite excellent accuracy.

WINNER XGBoost

Optimised gradient boosting with regularisation, parallel tree construction, and built-in handling for class imbalance (scale_pos_weight=4). 300 trees, max_depth=6. Achieves perfect recall (0.9998) in just 24 seconds — the ideal balance of accuracy and speed.

ML LightGBM

Leaf-wise gradient boosting with histogram-based splits. Fastest tree model (14s training). Matches XGBoost on F1 and recall but slightly slower inference. Excellent for production deployment.

DL MLP (GPU)

Multi-Layer Perceptron: 3 hidden layers (256→128→64), BatchNorm, ReLU, Dropout. Trained on RTX 3050 6GB. Architecture from Sakib & Tabassum (2025) who reported 99.97% accuracy on CICIDS2017 binary classification.

DL 1D-CNN (GPU)

Convolutional Neural Network treating 30 features as a 1D sequence. Extracts local patterns via learnable filters. Two Conv1d layers with BatchNorm, followed by dense classifier.

DL LSTM (GPU)

Long Short-Term Memory network — each feature treated as a timestep. 2-layer LSTM with hidden_size=64. Captures sequential dependencies in the feature vector. Slowest model (4,276s) due to sequential computation.

DL GRU (GPU)

Gated Recurrent Unit — lighter than LSTM with fewer parameters. Uses update and reset gates instead of LSTM's three-gate system. Similar accuracy to LSTM at lower training time.

DL BiLSTM (GPU)

Bidirectional LSTM — processes the feature sequence both forward and backward, capturing context from both directions. 64 hidden units per direction (128 total). Best DL model for DoS detection per Sakib & Tabassum (2025).

DL CNN+BiLSTM (GPU)

Hybrid: CNN extracts local feature patterns, BiLSTM captures sequential dependencies. Best DL model for Web Attack detection per Sakib & Tabassum (2025). Most complex architecture tested.

UNSUPERVISED Isolation Forest (Combined with XGBoost)

Tree-based anomaly detection — anomalous points are isolated with fewer splits than normal points. 100 trees, contamination=0.1. Trained on the training set without labels — pure unsupervised learning. Used alongside XGBoost in a hybrid scoring formula to detect zero-day attacks (novel attack patterns not present in training data).

Hybrid Score: attack_score = 0.5 × XGBoost_probability + 0.4 × IsoForest_anomaly_score
Isolation Forest's role is NOT measured by Accuracy/F1 — those metrics apply only to the supervised XGBoost. ISO adds zero-day detection capability that cannot be measured on labelled datasets.

Multi-Criteria Model Selection
Model selection was based on a weighted composite score across five dimensions rather than a single metric. F1 alone is insufficient for IDS — a model with perfect F1 but 10% false alarm rate causes alert fatigue where security analysts ignore alerts. The composite approach follows recommendations from recent IDS literature: "No single metric should be used in isolation" (Ross et al., Surgery 2023).
30%

Recall (Detection Rate)

Missing an attack is catastrophic. A missed ransomware flow can cost millions. Highest weight reflects security priority.

25%

F1 Score

Harmonic mean of precision and recall. Maintains comparability with all reference papers and handles class imbalance correctly.

20%

False Alarm Rate (FAR)

Too many false positives → alert fatigue → analysts ignore alerts → system becomes useless. Lower FAR = more trustworthy system. Inverted: lower FAR gives higher score.

15%

AUC-ROC

Threshold-independent measure of discrimination ability. Important because the dashboard allows threshold adjustment at runtime.

10%

Inference Speed

Real-time system must classify flows faster than they arrive. XGBoost at 0.00065ms/flow vs LSTM at 0.013ms/flow = 20x faster. Inverted: faster = higher score.

Composite Score = 0.30 × norm(Recall) + 0.25 × norm(F1) + 0.20 × (1−norm(FAR)) + 0.15 × norm(AUC) + 0.10 × (1−norm(Speed))

Each metric normalised to [0,1] before weighting to prevent scale bias

Why XGBoost was selected over LightGBM and Random Forest: All three achieve nearly identical F1 (0.9972). XGBoost wins on composite score (0.9948) because it has the best recall (0.9998 — only 19 attacks missed out of 85,176) combined with fast inference (0.00065ms) and perfect AUC (1.0000). LightGBM has identical recall but slower inference. Random Forest has marginally lower recall (misses 181 attacks vs XGBoost's 19).
XGBoost — Selected Model Deep Dive
Full name: eXtreme Gradient Boosting (XGBoost) — Chen & Guestrin, 2016
Type: Supervised, ensemble, gradient boosting
Parameters used: n_estimators=300, max_depth=6, learning_rate=0.1, subsample=0.8, colsample_bytree=0.8, scale_pos_weight=4
Training time: 24 seconds on full 2M+ row dataset
Inference time: 0.00065ms per flow — capable of classifying 1.5 million flows per second

How XGBoost Works

Step 1 — Initial prediction: Start with a simple base prediction (mean of all labels).
Step 2 — Compute residuals: Calculate the difference between predicted and actual labels. These are the "errors" the next tree must fix.
Step 3 — Train a tree on residuals: A new decision tree is trained to predict the residuals (errors), not the original labels.
Step 4 — Update prediction: Add the new tree's output × learning_rate (0.1) to the current prediction. Learning rate prevents overfitting by shrinking each tree's contribution.
Step 5 — Repeat 300 times: Each new tree corrects remaining errors. After 300 trees, the ensemble prediction is highly accurate.
Regularisation: L1 and L2 regularisation terms in the objective function prevent overfitting — distinguishes XGBoost from vanilla Gradient Boosting.
Class imbalance handling: scale_pos_weight=4 tells XGBoost to assign 4× more weight to the minority class (attacks), compensating for the 4.92:1 imbalance.

Isolation Forest — Unsupervised Anomaly Detector

How Isolation Forest Works

Core insight: Anomalies are easier to isolate than normal points. A normal flow surrounded by many similar flows requires many random splits to isolate. An anomalous flow surrounded by nothing similar is isolated in very few splits.
Building a tree: Randomly select a feature, then randomly select a split value between that feature's min and max. Recursively partition until each point is isolated or max depth reached.
Anomaly score: Average path length to isolate a point across 100 trees. Short path = anomaly. Long path = normal. Score is sigmoid-normalised to [0,1].
No labels required: Trained on the training set without using the Label column. It learns what "normal" traffic looks like purely from the data distribution.
Zero-day detection: Can flag attack patterns it has never seen before — if a flow deviates from learned normal patterns, it scores high regardless of attack type.

Hybrid Scoring with XGBoost

XGBoost contribution (α=0.5): Supervised probability that this flow matches known attack patterns. Highly accurate for attack types seen during training.
Isolation Forest contribution (β=0.4): Anomaly score — how different this flow is from normal traffic. Captures zero-day attacks that XGBoost cannot classify.
Combined formula:
attack_score = 0.5 × XGB_prob + 0.4 × ISO_anomaly_score
ISO_score = sigmoid(−iso_raw × 10)
label = "Attack" if attack_score ≥ threshold else "Benign"
Runtime tunable: α, β, and threshold are adjustable via the dashboard sliders without retraining — allowing security teams to tune sensitivity in real-time.
Why this combination: XGBoost alone may miss novel attack variants. Isolation Forest alone has high false alarm rate. Together they achieve higher recall while keeping FAR low.
